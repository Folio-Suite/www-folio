# Domain documentation

## Layout and reading rules

This repository uses a single context: `CONTEXT.md` at the root and architecture decisions in `docs/adr/`.

Before exploring domain behavior, read `CONTEXT.md` if present and the ADRs relevant to the area under discussion. If a root `CONTEXT-MAP.md` is introduced later, follow it to the relevant context documents and their ADR directories.

When those documents are absent, proceed silently. The domain-modeling skill creates them when terminology or decisions are resolved.

## Vocabulary

Use the glossary's established names in issues, design proposals, code, and tests. If a needed concept is missing, distinguish a real glossary gap from an unnecessary synonym and record real gaps for domain modeling.

## Decisions

Surface conflicts with existing ADRs explicitly, naming the decision and explaining why it may need reconsideration.
